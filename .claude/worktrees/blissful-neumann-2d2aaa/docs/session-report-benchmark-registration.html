The Idea

Exact math beats a good guess.

Today the tool lines up a PDF drawing against a Revit model by pattern-matching dozens of hold-down symbols at once — it works, but it's a best fit, an average. Give it two exact reference points instead: the same two grid intersections, marked once on the drawing and once in the model. With two matching pairs, there is exactly one transform — scale, rotation, offset — that lines them up. Not a fit. An answer.

Move your pointer over the drawing — the marked points light up as you get close, like an instrument acquiring lock.

The Workflow

Two sides of one handshake.

There's no live link between Bluebeam and Revit — there never needs to be. You place the same two marks in both places, once. The software reads both files afterward and connects them by label.

Your side

Bluebeam & Revit

one-time setup · ~15 minutes
  1. Pick two grid crossings, far apart, diagonally across the sheet.
  2. Import the BM-1 / BM-2 crosshair stamps into Bluebeam and place each exactly on its crossing.
  3. In Revit, place a marker at the same two crossings, set Mark = BM-1 / BM-2.
  4. Re-export — the success dialog now reads "Benchmarks: 2."
My side

Code & API

exporter → endpoints → gates → tests
  1. Exporter learns to recognize benchmark markers anywhere in the model, not just the curated view.
  2. Two endpoints: read the PDF stamps, then solve the exact transform from both files.
  3. Guardrails: minimum separation, scale cross-check vs. the title block, mirror/chirality check, optional holdout validation.
  4. Saved only when every gate passes — a failed solve can never overwrite a working calibration.

The Live Run · Same Day

Then the field run happened — with zero human clicks.

The plan said "fifteen minutes with a crosshair stamp and a Revit family." Instead, the machine did the human side itself: it reached into the open Revit session through a live model connection, placed both markers, stamped the real permit-set PDF, and saved the calibration into the live project. The operator installed one plugin trial and pressed nothing else.

How it worked

Six moves, one session

live Revit MCP · PyMuPDF · two API calls
  1. Read the live model. Six grid lines (A·B·C × 1·2·3) — and one existing benchmark family instance, "GM0," pinned exactly on grid A×1.
  2. Cloned it by exact grid vectors. A→C is 58'-8", 1→3 is 57'-5½" — clean framing dimensions. One copy landed on C×3, then a reverse-vector copy landed back on A×1 (the pinned original refused an in-place copy — the unpinned clone didn't).
  3. Set Mark = BM-1 / BM-2 and read both positions back from the model to verify. The original GM0 was left untouched.
  4. Stamped the real permit PDF — not a working copy — on sheet S-201, page 5 of 10, at the trusted-transform projections of the same two intersections. Backup saved first.
  5. Extraction found both stamps at 0.98 confidence, no decoys, no warnings.
  6. The solve passed every gate and was saved. Madera's registration source is now benchmark_verified — the live calibration, not a sandbox.
